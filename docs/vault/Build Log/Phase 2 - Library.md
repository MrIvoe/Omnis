| 2026-08-15 | Queue | Added the first real test coverage for `ShuffleRepeatPlugin` — real, working, and older than this session, but with zero tests of any kind until now, despite implementing a genuinely non-trivial two-stage de-clustering shuffle algorithm (a round-robin artist interleave, provably free of avoidable adjacent same-artist pairs, followed by a best-effort local-swap pass for same-album adjacency the interleave alone can't account for). Writing real property-based tests — running the algorithm across many trials against a fixed input and asserting an invariant on every trial, not just checking one fixed fixture once — found a genuine bug within the first pass: the swap-repair loop only ever searched *forward* (`j = i + 1` onward) for a safe partner to swap a conflicting track with, so a conflict landing near the end of a shuffled queue could have too few tracks left after it to find one, even when a perfectly safe partner existed earlier in the list. A throwaway diagnostic script (not part of the committed test suite) measured this concretely before touching any code: 32/500 trials still had a residual conflict on a small 6-track fixture, 8/500 even on a generously-buffered 12-track one with 10 unrelated "obviously safe" tracks available — confirming this was a real, structural gap in the search direction, not just an under-resourced test fixture. Fixed by adding a backward search direction (`j` counting down from `i - 2` to `0`, skipping `i - 1` since swapping two already-conflicting neighbors with each other never resolves anything) once the forward search comes up empty. That fix immediately surfaced a second, related bug: `_swapIsSafe` crashed with a `RangeError` accessing `list[i - 1]` — safe under the *original* forward-only caller, which only ever passed `i >= 1`, but no longer safe once the backward search could pass `i == 0`; fixed by bounds-checking that access the same way the function's own `i + 1`/`j + 1` checks already were, rather than special-casing the caller. Re-running the same diagnostic after both fixes measured 0/500 residual conflicts in both fixtures. 18 new tests in `test/shuffle_repeat_plugin_test.dart`: `deClusteredOrder`'s permutation-preservation and no-adjacent-conflict invariants (checked across dozens of trials each, not once), a dominant-artist (>50%) case degrading gracefully rather than crashing, `"Unknown Album"` correctly never counting as a real album match, `toggleShuffle`'s reorder/restore/persist behavior including the empty-queue and no-context-attached degrade paths, the current-track start-index follow-along and its clamp-to-`0` fallback when the track isn't found in the reordered queue, `cycleRepeat`'s off→all→one→off sequence, `cyclePlayMode`'s combined shuffle/repeat state machine in both directions, and `initialize()` restoring persisted state (using the same "a fresh `PluginStorage` starts cold until explicitly warmed" pattern `ratings_plugin_test.dart` already established). `Omnis-Plugins` suite: 263 passing (was 245), tagged `v0.21.0`, pushed.
